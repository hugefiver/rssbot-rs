# AGENTS.md

## Build & Toolchain

- **Rust Nightly required** (edition 2024). No `rust-toolchain` file; CI pins nightly via `dtolnay/rust-toolchain@nightly`.
- Build: `cargo build --release` → binary at `target/release/rssbot`
- Lint: `cargo clippy --no-deps --all-targets`
- Test: `cargo test -v`
- Run a single test: `cargo test <test_name> -- --nocapture` (tests are inline `#[cfg(test)]` modules, not in separate test files)

## Localization (compile-time)

- The `LOCALE` env var selects which `locales/{zh,en}.toml` gets compiled in (default: `zh`).
- CI checks both locales with `$env:LOCALE="en"; cargo check` (or `zh`).
- The `tr!("key")` macro is generated by the `ctl10n` build dependency and included via `include!()` in `main.rs`. **Do not remove or refactor `tr!()` usage** — it's the only i18n mechanism.

## Features

- `default = ["rustls"]` — rustls TLS (default). `native-tls` is the alternative; never enable both.
- `hosted-by-iovxw` — enables a 1500-feed subscription cap (used in production). Not required for local dev.

## Architecture (single binary)

| File | Role |
|------|------|
| `src/main.rs` | CLI (clap), bot init (teloxide), panic=fail-fast (exit 101) |
| `src/commands.rs` | Command dispatch + auth (admin/restricted mode checks) |
| `src/commands/*.rs` | `/start`, `/sub`, `/unsub`, `/export`, `/rss` handlers |
| `src/feed.rs` | RSS/Atom/JSON Feed XML parser (quick-xml, manual SAX-style) |
| `src/data.rs` | JSON file DB with atomic writes (`atomicwrites`), custom `Size64Hasher` |
| `src/fetcher.rs` | Background feed polling with `Throttle` (staggered fetch timings) |
| `src/client.rs` | reqwest client (10s timeout, custom UA, `RSSBOT_DONT_PROXY_FEEDS` env) |
| `src/gardener.rs` | Daily prune of left/banned subscribers |
| `src/messages.rs` | Telegram message chunking (4096 char limit), HTML escaping |
| `src/opml.rs` | OPML export generator |

## Key Gotchas

- **`enable_fail_fast()`** in `main.rs:244` calls `process::exit(101)` on any worker thread panic. This means a single panic kills the process — not just the task.
- **`Size64Hasher`** (`data.rs:309`) only works with `u64`/`i64` keys. Passing any other type panics.
- **JSON Feed** support is handled via serde deserialization (`client.rs:55-61`), not the XML parser.
- **`max_feed_size`** accepts human-readable sizes like `"2M"`, `"2G"` — parsed by `parse_human_size()` in `main.rs`.
- Feed IDs and item hashes are computed via `DefaultHasher` on strings — **never change the hashing** or existing subscribers would lose their feed histories.
- The database is a flat JSON array of `Feed` structs, atomically written on every mutation (`atomicwrites` with `AllowOverwrite`).

## CI / Release

- CI triggers on `push` and runs `clippy` + `test` on ubuntu/windows/macOS.
- Docker builds push to `ghcr.io` with per-locale tags (`ghcr.io/<owner>/rssbot_zh`, `rssbot_en`).
- Release workflow cross-compiles (via `houseabsolute/actions-rust-cross`) for multiple Linux/Windows targets per locale.

## Proxy

- Set `$env:RSSBOT_DONT_PROXY_FEEDS` to any value to disable the system proxy for feed requests. By default, the reqwest client uses the system proxy (unless built with `no_proxy`).
